## 9. 建立 C# API、資料契約與設定入口

### 9.1 API 契約先講清楚

主線使用四個欄位：`name`、`priceInCents`、`stock`、`isActive`；讀取結果另有 `id`。`priceInCents = 120000` 代表 1,200.00 元。金額值域限制為 0～100,000,000 分，庫存為 0～1,000,000 的整數，名稱去掉前後空白後長度為 1～80。

| 動作 | API | 成功回應 | 需要呈現的失敗 |
|---|---|---|---|
| 查詢 | `GET /api/products?q=鍵盤` | Product[] | 網路失敗、500 |
| 讀取 | `GET /api/products/{id}` | Product | 404 |
| 新增 | `POST /api/products` | 201、Product | 400 |
| 更新 | `PUT /api/products/{id}` | Product | 400、404、409 |
| 刪除 | `DELETE /api/products/{id}` | 204 | 404 |

### 9.2 C# 練習 API

在 Angular 資料夾以外建立另一個專案，例如兩者都位於 `angular-learning` 下。使用已安裝的 .NET 10 SDK：

```bash
dotnet new web -n ProductApi --framework net10.0
cd ProductApi
```

實作檔案：後端專案 `Program.cs`，完整替換如下。這是記憶體練習 API，重新啟動後資料會重設；刻意省略資料庫、登入及正式記錄設定。驗證以明確程式碼實作，不假設 DTO 自動驗證已啟用。[O12]

<!-- backend-file: Program.cs -->
```csharp
using System.Collections.Concurrent;

var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();

var products = new ConcurrentDictionary<int, Product>();
products[1] = new Product(1, "鍵盤", 120000, 10, true);
products[2] = new Product(2, "滑鼠", 60000, 0, false);
var nextId = 2;

app.MapGet("/api/products", (string? q) =>
{
    var keyword = q?.Trim() ?? "";
    return products.Values
        .Where(p => p.Name.Contains(keyword, StringComparison.OrdinalIgnoreCase))
        .OrderBy(p => p.Id)
        .ToArray();
});

app.MapGet("/api/products/{id:int}", IResult (int id) =>
    products.TryGetValue(id, out var product)
        ? Results.Ok(product)
        : Results.NotFound());

app.MapPost("/api/products", IResult (ProductWrite request) =>
{
    var errors = Validate(request);
    if (errors.Count > 0) return Results.ValidationProblem(errors);

    var id = Interlocked.Increment(ref nextId);
    var product = new Product(id, request.Name!.Trim(),
        request.PriceInCents, request.Stock, request.IsActive);
    products[id] = product;
    return Results.Created($"/api/products/{id}", product);
});

app.MapPut("/api/products/{id:int}", IResult (int id, ProductWrite request) =>
{
    var errors = Validate(request);
    if (errors.Count > 0) return Results.ValidationProblem(errors);
    if (!products.TryGetValue(id, out var old)) return Results.NotFound();

    var product = new Product(id, request.Name!.Trim(),
        request.PriceInCents, request.Stock, request.IsActive);
    if (!products.TryUpdate(id, product, old))
        return Results.Conflict(new { message = "資料已變動，請重新讀取。" });
    return Results.Ok(product);
});

app.MapDelete("/api/products/{id:int}", IResult (int id) =>
    products.TryRemove(id, out _)
        ? Results.NoContent()
        : Results.NotFound());

app.Run();

static Dictionary<string, string[]> Validate(ProductWrite request)
{
    var errors = new Dictionary<string, string[]>();
    if (string.IsNullOrWhiteSpace(request.Name) || request.Name.Trim().Length > 80)
        errors["name"] = ["名稱去除前後空白後，須為 1～80 個字元。"];
    if (request.PriceInCents is < 0 or > 100_000_000)
        errors["priceInCents"] = ["金額須為 0～100,000,000 分。"];
    if (request.Stock is < 0 or > 1_000_000)
        errors["stock"] = ["庫存須為 0～1,000,000。"];
    return errors;
}

public record Product(int Id, string Name, int PriceInCents, int Stock, bool IsActive);
public record ProductWrite(string? Name, int PriceInCents, int Stock, bool IsActive);
```

```bash
dotnet run --no-launch-profile --urls http://localhost:5000
```

先直接查看 [http://localhost:5000/api/products](http://localhost:5000/api/products)。ASP.NET Core 預設 web JSON 命名規則會將 `PriceInCents` 等名稱輸出為 camelCase，與前端契約一致。`TryUpdate` 只保護這次記憶體操作的競爭，沒有實作跨使用者編輯版本檢查；正式專案另以 rowversion/ETag 等機制處理。

<!-- file: src/app/core/public-config.ts -->
```typescript
import { InjectionToken } from '@angular/core';

export interface PublicConfig {
  apiBaseUrl: string;
  environmentName: string;
}

export const PUBLIC_CONFIG = new InjectionToken<PublicConfig>('public-config');

export async function loadPublicConfig(): Promise<PublicConfig> {
  const response = await fetch('/app-config.json', { cache: 'no-store' });
  if (!response.ok) throw new Error('公開設定載入失敗');

  const raw: unknown = await response.json();
  if (typeof raw !== 'object' || raw === null) throw new Error('設定格式錯誤');

  const value = raw as Record<string, unknown>;
  const apiBaseUrl = value['apiBaseUrl'];
  const environmentName = value['environmentName'];
  if (typeof apiBaseUrl !== 'string' || typeof environmentName !== 'string') {
    throw new Error('設定缺少必要字串欄位');
  }

  // 本教材固定部署於網域根目錄；API 使用同源 /api 或 HTTPS 絕對網址。
  if (apiBaseUrl !== '/api') {
    const url = new URL(apiBaseUrl);
    if (url.protocol !== 'https:' || url.username || url.password || url.search || url.hash) {
      throw new Error('API 網址不符合設定要求');
    }
  }
  return { apiBaseUrl: apiBaseUrl.replace(/\/+$/, ''), environmentName };
}
```

此處的檢查只針對公開設定契約，不是所有 API 資料的通用驗證器。若部署在 `/admin/` 子路徑，須一併調整 base href、設定載入路徑與 Nginx 路徑；不要直接沿用根目錄假設。

### 9.6 API 服務

實作檔案：`src/app/features/products/product-api.ts`。

<!-- file: src/app/features/products/product-api.ts -->
```typescript
import { Injectable, inject } from '@angular/core';
import { HttpClient, HttpErrorResponse } from '@angular/common/http';
import { PUBLIC_CONFIG } from '../../core/public-config';
import type { Product, ProductWrite } from './product';

@Injectable({ providedIn: 'root' })
export class ProductApi {
  private readonly http = inject(HttpClient);
  private readonly config = inject(PUBLIC_CONFIG);
  readonly baseUrl = `${this.config.apiBaseUrl}/products`;

  get(id: number) { return this.http.get<Product>(`${this.baseUrl}/${id}`); }
  create(value: ProductWrite) { return this.http.post<Product>(this.baseUrl, value); }
  update(id: number, value: ProductWrite) {
    return this.http.put<Product>(`${this.baseUrl}/${id}`, value);
  }
  remove(id: number) { return this.http.delete<void>(`${this.baseUrl}/${id}`); }
}

export function apiErrorMessage(error: unknown): string {
  if (!(error instanceof HttpErrorResponse)) return '操作失敗，請稍後重試。';
  if (error.status === 0) return '無法連線，請檢查網路與 API。';
  if (error.status === 400) return '資料驗證失敗，請檢查名稱、金額及庫存。';
  if (error.status === 401) return '登入狀態已失效。';
  if (error.status === 403) return '沒有執行此操作的權限。';
  if (error.status === 404) return '資料已不存在，請重新查詢。';
  if (error.status === 409) return '資料發生衝突，請重新讀取後再試。';
  return '伺服器處理失敗，請稍後重試。';
}
```

錯誤訊息是 UI 層的可理解說明。正式表單可進一步將 ValidationProblem 的 `errors` 對應欄位；避免直接將所有伺服器錯誤內容或堆疊顯示給使用者。

**練習與完成條件：**直接開啟 API 能取得 JSON；經由 4200 的開發代理也能取得相同資料；刪除或破壞設定檔時，畫面停止啟動且不向其他環境送出請求。

## 10. 使用 httpResource 建立產品清單

### 10.1 先理解它解決的問題

傳統方式常要自己保存資料、loading、error 及過期請求的處理。`httpResource` 將查詢結果與狀態提供為 Signals，並在查詢相依的 Signal 改變時重新請求。它會主動發出查詢，與通常等到訂閱才執行的 HttpClient Observable 不同。[O13]

主線使用兩個搜尋值：`keyword` 是正在輸入的文字，`query` 是已提交的查詢。只有按下搜尋才更新 query，初學時先避免每個按鍵都發出請求。即時搜尋與 debounce 留作練習。

### 10.2 完整清單頁

實作檔案：`src/app/features/products/product-list.ts`。

<!-- file: src/app/features/products/product-list.ts -->
```typescript
import { Component, inject, signal } from '@angular/core';
import { CurrencyPipe } from '@angular/common';
import { httpResource } from '@angular/common/http';
import { RouterLink } from '@angular/router';
import { firstValueFrom } from 'rxjs';
import { ProductApi, apiErrorMessage } from './product-api';
import type { Product } from './product';

@Component({
  selector: 'app-product-list',
  standalone: true,
  imports: [RouterLink, CurrencyPipe],
  template: `
    <h1>產品清單</h1>
    <a routerLink="/products/new">新增產品</a>
    <form (submit)="search($event)">
      <label for="keyword">產品名稱</label>
      <input id="keyword" #searchBox [value]="keyword()"
        (input)="keyword.set(searchBox.value)" />
      <button type="submit">搜尋</button>
      <button type="button" (click)="products.reload()">重新載入</button>
    </form>

    @if (operationError()) {
      <p role="alert">{{ operationError() }}</p>
    }
    @if (products.isLoading()) {
      <p role="status">載入中</p>
    } @else if (products.error()) {
      <p role="alert">{{ loadError() }}</p>
    } @else if (products.hasValue()) {
      <table>
        <caption>產品查詢結果</caption>
        <thead>
          <tr><th scope="col">名稱</th><th scope="col">價格</th>
            <th scope="col">庫存</th><th scope="col">狀態</th>
            <th scope="col">操作</th></tr>
        </thead>
        <tbody>
          @for (product of products.value(); track product.id) {
            <tr>
              <td>{{ product.name }}</td>
              <td>{{ product.priceInCents / 100 | currency:'TWD':'symbol':'1.2-2' }}</td>
              <td>{{ product.stock }}</td>
              <td>{{ product.isActive ? '上架' : '下架' }}</td>
              <td>
                <a [routerLink]="['/products', product.id, 'edit']">編輯</a>
                <button type="button" [disabled]="deleting()"
                  [attr.aria-label]="'刪除 ' + product.name"
                  (click)="remove(product)">刪除</button>
              </td>
            </tr>
          } @empty {
            <tr><td colspan="5">沒有符合條件的產品</td></tr>
          }
        </tbody>
      </table>
    }
  `
})
export class ProductList {
  private readonly api = inject(ProductApi);
  readonly keyword = signal('');
  readonly query = signal('');
  readonly deleting = signal(false);
  readonly operationError = signal('');

  readonly products = httpResource<Product[]>(() => ({
    url: this.api.baseUrl,
    params: { q: this.query() }
  }));

  search(event: Event): void {
    event.preventDefault();
    const next = this.keyword().trim();
    if (next === this.query()) this.products.reload();
    else this.query.set(next);
  }

  loadError(): string { return apiErrorMessage(this.products.error()); }

  async remove(product: Product): Promise<void> {
    if (this.deleting() || !window.confirm(`刪除「${product.name}」？`)) return;
    this.deleting.set(true);
    this.operationError.set('');
    try {
      await firstValueFrom(this.api.remove(product.id));
      this.products.reload();
    } catch (error) {
      this.operationError.set(apiErrorMessage(error));
    } finally {
      this.deleting.set(false);
    }
  }
}
```

### 10.3 讀取與寫入分開

查詢採 httpResource；刪除採使用者明確觸發的 HttpClient，成功後 `reload()`。不要把刪除或儲存放在會隨狀態重跑的 resource loader。

`firstValueFrom()` 將此處單次 HTTP 回應轉為 Promise，讓 `try/catch/finally` 容易閱讀。它不是將所有 Observable 都安全轉成 Promise 的通用策略：來源若永不發值或完成，Promise 可能一直等待；長期或可取消的畫面訂閱仍需生命週期管理。

刪除中的旗標避免此頁面連點，但不能防止其他分頁或網路重送。可靠的寫入仍靠後端設計。

### 10.4 hasValue 與錯誤順序

本例先顯示載入，再判斷錯誤，確認 `hasValue()` 後才讀取 `value()`。resource 在錯誤狀態讀取值可能拋出例外，不要無條件在任意運算中讀取 `value()`；預設空陣列也無法代表所有錯誤都可忽略。[O14]

範例使用 `window.confirm()` 是為了減少對話框實作範圍。正式介面可改成具備焦點管理的可存取對話框；確認機制和真正的刪除權限仍是兩個問題。

**練習與完成條件：**搜尋有結果、無結果、API 關閉及刪除失敗時都有對應畫面；成功刪除後清單刷新；同一個關鍵字再次提交會重新查詢。

### 10.5 原文對照：`httpResource()` 正式穩定，告別載入狀態旗標

> 摘自原文 6《Angular 22 的 7 項變更》第 3 項。

**問題**：算算看這段程式碼你寫過多少次：

```typescript
user: User | null = null;
loading = false;
error = '';

ngOnInit() {
  this.loading = true;
  this.http.get<User>(`/api/users/${this.id}`).subscribe({
    next: u => { this.user = u; this.loading = false; },
    error: () => { this.error = 'Failed'; this.loading = false; }
  });
}
```

三個欄位、一個訂閱，還藏著一個錯誤：如果 `id` 快速變更，舊請求的回應可能比新請求更晚抵達，導致畫面顯示錯誤的使用者（競態條件，race condition）。

**變更**：`resource()`、`rxResource()` 和 `httpResource()` 都已正式穩定。

```typescript
id = input.required<string>();
user = httpResource<User>(() => `/api/users/${this.id()}`);
```

```html
@if (user.isLoading()) {
  <app-spinner />
} @else if (user.error()) {
  <p>Could not load this user.</p>
} @else {
  <h2>{{ user.value()?.name }}</h2>
}
```

![httpResource 流程](https://hackmd.io/_uploads/SJw5QlfTMx.png)

`httpResource()` 的參數是一個會讀 signal 的函式：當 `this.id()` 改變，它自動重新請求，並自動丟棄過期回應。原文 1 補充：這些 API 可與 Angular 的響應式相依關係圖及伺服器端的狀態轉移（Transfer State）機制順暢整合。

**結果**：

| 指標 | subscribe() | httpResource() |
|---|---:|---:|
| 程式碼行數 | 14 | 2 |
| 手動管理的狀態欄位數 | 3 | 0 |
| 過期回應造成的錯誤 | 可能發生 | 自動處理 |

> 💡 **C# 工程師這樣想**：這相當於把「手寫 `IsBusy` / `Error` / `Data` 三個屬性 + `CancellationTokenSource` 取消前一次請求」的樣板，換成一個會自動追蹤輸入、自動取消舊請求的 `IAsyncResource<T>`。`resource()` 是通用版本（自己給一個回傳 Promise 的 loader）；`rxResource()` 接 Observable；`httpResource()` 專門給 HTTP。

## 11. Reactive Forms：完成新增與編輯

### 11.1 先理解表單模型

Reactive Forms 使用 `FormControl` 表示欄位，`FormGroup` 表示欄位群組。表單模型保存值、錯誤、是否改動、是否接觸等狀態。這套 API 仍受支援，學會後也能讀懂大量既有 Angular 專案。[O15]

| 表單狀態 | 意義 |
|---|---|
| `valid` / `invalid` | 是否通過驗證 |
| `touched` | 使用者是否曾離開欄位 |
| `dirty` | 使用者是否改過值 |
| `pending` | 非同步驗證尚未完成 |
| `disabled` | 欄位被停用；FormGroup.value 可能不包含它 |

`getRawValue()` 包含停用欄位。它是否適合當作 API 輸入，要依契約判斷，不能藉此把不該由使用者變更的欄位送回伺服器。

### 11.2 驗證函式

實作檔案：`src/app/features/products/product-validators.ts`。

<!-- file: src/app/features/products/product-validators.ts -->
```typescript
import type { AbstractControl, ValidationErrors } from '@angular/forms';

export function trimmedNameValidator(control: AbstractControl): ValidationErrors | null {
  const value: unknown = control.value;
  return typeof value === 'string' && value.trim().length >= 1 && value.trim().length <= 80
    ? null : { trimmedName: true };
}

export function wholeNumberValidator(control: AbstractControl): ValidationErrors | null {
  return typeof control.value === 'number' && Number.isSafeInteger(control.value)
    ? null : { wholeNumber: true };
}
```

`type="number"` 是輸入提示，不是完整驗證規則；小數、空值和越界仍需檢查。名稱只含空白時，也不應通過驗證。

### 11.3 完整編輯頁

實作檔案：`src/app/features/products/product-edit.ts`。

<!-- file: src/app/features/products/product-edit.ts -->
```typescript
import { Component, DestroyRef, inject, signal } from '@angular/core';
import { takeUntilDestroyed } from '@angular/core/rxjs-interop';
import { FormControl, FormGroup, ReactiveFormsModule, Validators } from '@angular/forms';
import { ActivatedRoute, Router, RouterLink } from '@angular/router';
import { catchError, firstValueFrom, map, of, switchMap } from 'rxjs';
import { ProductApi, apiErrorMessage } from './product-api';
import { trimmedNameValidator, wholeNumberValidator } from './product-validators';
import type { Product } from './product';

interface EditLoad {
  id: number | null;
  product: Product | null;
  error: string;
}

@Component({
  selector: 'app-product-edit',
  standalone: true,
  imports: [ReactiveFormsModule, RouterLink],
  template: `
    <h1>{{ id() === null ? '新增產品' : '編輯產品' }}</h1>
    <a routerLink="/products">返回清單</a>
    @if (loading()) {
      <p role="status">載入中</p>
    } @else if (loadError()) {
      <p role="alert">{{ loadError() }}</p>
    } @else {
      <form [formGroup]="form" (ngSubmit)="save()">
        <label for="name">名稱</label>
        <input id="name" formControlName="name" aria-describedby="name-error"
          [attr.aria-invalid]="form.controls.name.touched && form.controls.name.invalid" />
        <p id="name-error">
          @if (form.controls.name.touched && form.controls.name.invalid) {
            名稱去除前後空白後，須為 1～80 個字元。
          }
        </p>

        <label for="price">金額（分；100 分 = 1 元）</label>
        <input id="price" type="number" min="0" step="1"
          formControlName="priceInCents" aria-describedby="price-error"
          [attr.aria-invalid]="form.controls.priceInCents.touched && form.controls.priceInCents.invalid" />
        <p id="price-error">
          @if (form.controls.priceInCents.touched && form.controls.priceInCents.invalid) {
            金額須為 0～100,000,000 的整數。
          }
        </p>

        <label for="stock">庫存</label>
        <input id="stock" type="number" min="0" step="1"
          formControlName="stock" aria-describedby="stock-error"
          [attr.aria-invalid]="form.controls.stock.touched && form.controls.stock.invalid" />
        <p id="stock-error">
          @if (form.controls.stock.touched && form.controls.stock.invalid) {
            庫存須為 0～1,000,000 的整數。
          }
        </p>

        <label><input type="checkbox" formControlName="isActive" />上架</label>
        @if (saveError()) { <p role="alert">{{ saveError() }}</p> }
        @if (saving()) { <p role="status">儲存中</p> }
        <button type="submit" [disabled]="saving()">儲存</button>
      </form>
    }
  `
})
export class ProductEdit {
  private readonly api = inject(ProductApi);
  private readonly route = inject(ActivatedRoute);
  private readonly router = inject(Router);
  private readonly destroyRef = inject(DestroyRef);

  readonly id = signal<number | null>(null);
  readonly loading = signal(true);
  readonly saving = signal(false);
  readonly loadError = signal('');
  readonly saveError = signal('');

  readonly form = new FormGroup({
    name: new FormControl('', { nonNullable: true, validators: [trimmedNameValidator] }),
    priceInCents: new FormControl(0, { nonNullable: true, validators: [
      Validators.required, wholeNumberValidator, Validators.min(0), Validators.max(100_000_000)
    ] }),
    stock: new FormControl(0, { nonNullable: true, validators: [
      Validators.required, wholeNumberValidator, Validators.min(0), Validators.max(1_000_000)
    ] }),
    isActive: new FormControl(true, { nonNullable: true })
  });

  constructor() {
    this.route.paramMap.pipe(
      switchMap(params => {
        this.loading.set(true);
        this.loadError.set('');
        this.saveError.set('');
        const raw = params.get('id');
        if (raw === null) return of<EditLoad>({ id: null, product: null, error: '' });

        const id = Number(raw);
        if (!Number.isSafeInteger(id) || id <= 0) {
          return of<EditLoad>({ id: null, product: null, error: '產品編號不正確。' });
        }
        return this.api.get(id).pipe(
          map(product => ({ id, product, error: '' } as EditLoad)),
          catchError(error => of<EditLoad>({ id, product: null, error: apiErrorMessage(error) }))
        );
      }),
      takeUntilDestroyed(this.destroyRef)
    ).subscribe(result => {
      this.id.set(result.id);
      this.loadError.set(result.error);
      const p = result.product;
      this.form.reset({
        name: p?.name ?? '',
        priceInCents: p?.priceInCents ?? 0,
        stock: p?.stock ?? 0,
        isActive: p?.isActive ?? true
      });
      this.loading.set(false);
    });
  }

  async save(): Promise<void> {
    if (this.saving() || this.loading() || this.loadError()) return;
    this.form.markAllAsTouched();
    if (this.form.invalid || this.form.pending) return;

    this.saving.set(true);
    this.saveError.set('');
    const value = this.form.getRawValue();
    value.name = value.name.trim();
    const id = this.id();
    try {
      const request$ = id === null ? this.api.create(value) : this.api.update(id, value);
      await firstValueFrom(request$);
      await this.router.navigateByUrl('/products');
    } catch (error) {
      this.saveError.set(apiErrorMessage(error));
    } finally {
      this.saving.set(false);
    }
  }
}
```

### 11.4 理解範例的取捨

主線用按下儲存後 `markAllAsTouched()` 顯示所有錯誤，不單靠停用按鈕提示使用者。API 失敗時保留表單內容；只有成功才返回清單。切換產品 ID 時，`switchMap` 取消前一筆讀取的訂閱。

Reactive Forms 的欄位狀態不是 Signal；本例的輸入與提交事件會觸發相關檢查，API 回應也更新 `loading` 等 Signals。若要從表單變化建立 Signal 衍生值，可用 `toSignal(form.valueChanges, ...)` 明確轉接，不要寫 `computed(() => this.form.value)` 後期待它自動追蹤一般屬性。

範例沒有未儲存提醒。下一步可實作 CanDeactivate，在使用者離開 dirty 表單時處理提醒；成功儲存與放棄變更則要明確更新判斷依據。

**練習與完成條件：**新增、編輯均可成功；空白名稱、小數庫存、負數金額被拒絕；404 不顯示可儲存的空白編輯表單；儲存失敗保留輸入，成功才導覽。

## 12. Signal Forms：用同一問題理解另一種表單

### 12.1 資料模型是來源

Signal Forms 自 Angular 22 起為穩定 API，資料放在可寫入 Signal，`form()` 在其上建立欄位樹，`FormField` 將欄位接到 HTML。[O36] Reactive Forms 仍可繼續使用，不需要先重寫所有舊表單。[O16]

| 面向 | Reactive Forms | Signal Forms |
|---|---|---|
| 主要值來源 | FormControl/FormGroup | 自己宣告的可寫入 Signal |
| 欄位繫結 | formControlName / formControl | `[formField]` |
| 驗證規則 | 控制項的 validators | 欄位路徑上的 schema 規則 |
| 值與狀態 | 屬性與 Observable | 模型與欄位狀態 Signals |
| 適合學習目的 | 維護大量既有專案 | 建立以 Signals 為主的新表單 |

### 12.2 可接入主線的新增示範

此範例是**新增頁面的額外版本**，不替換第 11 章編輯功能。檔案位置 `src/app/features/products/product-signal-demo.ts`。

<!-- file: src/app/features/products/product-signal-demo.ts -->
```typescript
import { Component, inject, signal } from '@angular/core';
import { FormField, form, max, min, validate } from '@angular/forms/signals';
import { Router, RouterLink } from '@angular/router';
import { firstValueFrom } from 'rxjs';
import { ProductApi, apiErrorMessage } from './product-api';
import type { ProductWrite } from './product';

@Component({
  selector: 'app-product-signal-demo',
  standalone: true,
  imports: [FormField, RouterLink],
  template: `
    <h1>Signal Forms 新增示範</h1>
    <a routerLink="/products">返回清單</a>
    <form (submit)="save($event)">
      <label>名稱<input [formField]="fields.name" /></label>
      <label>金額（分）<input type="number" [formField]="fields.priceInCents" /></label>
      <label>庫存<input type="number" [formField]="fields.stock" /></label>
      <label><input type="checkbox" [formField]="fields.isActive" />上架</label>
      @if (submitted()) {
        @for (error of fields().errorSummary(); track error) {
          <p role="alert">{{ error.message }}</p>
        }
      }
      @if (message()) { <p role="alert">{{ message() }}</p> }
      <button type="submit" [disabled]="saving()">儲存</button>
    </form>
  `
})
export class ProductSignalDemo {
  private readonly api = inject(ProductApi);
  private readonly router = inject(Router);
  readonly saving = signal(false);
  readonly submitted = signal(false);
  readonly message = signal('');
  readonly model = signal<ProductWrite>({
    name: '', priceInCents: 0, stock: 0, isActive: true
  });

  readonly fields = form(this.model, path => {
    validate(path.name, ({ value }) => {
      const length = value().trim().length;
      return length >= 1 && length <= 80 ? null
        : { kind: 'name', message: '名稱去除前後空白後，須為 1～80 個字元。' };
    });
    min(path.priceInCents, 0, { message: '金額不可小於零。' });
    max(path.priceInCents, 100_000_000, { message: '金額超過上限。' });
    min(path.stock, 0, { message: '庫存不可小於零。' });
    max(path.stock, 1_000_000, { message: '庫存超過上限。' });
    validate(path.priceInCents, ({ value }) => Number.isSafeInteger(value()) ? null
      : { kind: 'integer', message: '金額須為整數分。' });
    validate(path.stock, ({ value }) => Number.isSafeInteger(value()) ? null
      : { kind: 'integer', message: '庫存須為整數。' });
  });

  async save(event: Event): Promise<void> {
    event.preventDefault();
    this.submitted.set(true);
    if (this.saving() || this.fields().invalid() || this.fields().pending()) return;
    this.saving.set(true);
    this.message.set('');
    try {
      const value = this.model();
      await firstValueFrom(this.api.create({ ...value, name: value.name.trim() }));
      await this.router.navigateByUrl('/products');
    } catch (error) {
      this.message.set(apiErrorMessage(error));
    } finally {
      this.saving.set(false);
    }
  }
}
```

### 12.3 不要在同一欄位綁兩套表單

不要把 `[formField]`、`formControlName` 與 `[(ngModel)]` 同時綁在同一個輸入欄位。這會造成多個狀態來源與不同驗證流程。漸進導入時，以完整表單或清楚的元件邊界分隔，確認自訂控制項與第三方套件的相容性。

**練習與完成條件：**以兩種表單完成相同新增規則，指出資料目前存放在哪裡；比較空白、數字清除、小數、儲存失敗與連點行為，不只比較程式碼行數。

### 12.4 原文對照：Signal Forms 正式穩定

> 摘自原文 6《Angular 22 的 7 項變更》第 2 項與原文 1。

**問題**：響應式表單（Reactive Forms）帶來 `FormGroup`、`FormControl`、`valueChanges` 訂閱，以及每個自訂輸入元件都要實作的 `ControlValueAccessor`。功能強大，但要向新進同事解釋清楚，得先準備一塊白板。

```typescript
form = new FormGroup({
  email: new FormControl('', [Validators.required, Validators.email]),
  pass: new FormControl('', Validators.required)
});
```

**變更**：Signal Forms（`@angular/forms/signals`）不再是實驗性功能。資料存放在 signal 中，表單建立在這份資料之上。

```typescript
import { form, FormField, required, email } from '@angular/forms/signals';

@Component({
  selector: 'app-login',
  imports: [FormField],
  template: `
    <input [formField]="login.email" />
    <input type="password" [formField]="login.pass" />
    <button [disabled]="login().invalid()">Sign in</button>
  `
})
export class Login {
  model = signal({ email: '', pass: '' });

  login = form(this.model, (f) => {
    required(f.email);
    email(f.email);
    required(f.pass);
  });
}
```

官方文件補充：`FormField` 指令必須 `import` 進任何要把欄位繫結到 HTML input 的元件；Signal Forms 需要 Angular v21 以上。

**結果**：

- 表單型別完整依據資料模型推導，不需要型別轉換，也不需要猜測。
- 不再有可能忘記處理的 `valueChanges` 訂閱。
- 自訂輸入元件不再需要 `ControlValueAccessor`。
- 新的輔助函式，例如 `debounce(f.pass, 'blur')` 和 `minDate()`，涵蓋了過去必須自行實作的需求。

原文 6 的實際建議：不要這個星期就重寫那份有四十個欄位的結帳表單。**先在下一份表單使用 Signal Forms**，前十分鐘就會察覺差異。原文 1 的說法則更直接：「需要撰寫大量 `FormGroup`、`FormControl`，以及訂閱 RxJS `valueChanges` 的時代已經結束。」

> 📌 **校正（依本教材第 0.3 節）**：原文 1 把 `FormGroup` 描述成「已棄用的技術債」，這**並不正確**。Reactive Forms（`FormGroup`、`FormControl`）在 Angular 22 仍受完整支援；Signal Forms 是**另一種**正式穩定的表單做法，不是取代品。既有專案的 Reactive Forms 不需要重寫，新表單可以評估改用 Signal Forms。本教材第 11 章與第 12 章用同一個「產品編輯」問題分別以兩種表單實作，是最好的對照材料；它也提醒**不要在同一個欄位同時綁兩套表單**（`formControlName` 與 `[formField]` 不能混用）。

> 💡 **C# 工程師這樣想**：`model = signal({ email: '', pass: '' })` 是你的 DTO；`form(model, schema)` 像對這個 DTO 套上一組 DataAnnotations（`required`、`email`），而 `login.email` 的型別自動從 DTO 推導──不用再像 `FormControl<string | null>` 那樣手動對型別。

### 13.3 操作驗收

| 情境 | 具體操作 | 預期行為 |
|---|---|---|
| 初次載入 | 開啟 `/products` | 顯示兩筆起始資料 |
| 搜尋 | 查詢「鍵盤」，再查不存在的名稱 | 分別出現一筆與空資料提示 |
| 新增 | 儲存合法產品 | 返回清單，出現新產品 |
| 修改 | 改名稱與庫存後儲存 | 返回清單，資料更新 |
| 驗證 | 名稱填空白、庫存 1.5 | 不送出成功寫入，顯示規則 |
| API 驗證 | 直接向 API POST 非法數值 | API 回傳 400，不能只靠前端擋 |
| 不存在 | 瀏覽 `/products/999999/edit` | 顯示找不到資料，不出現可提交空表單 |
| 斷線 | 停止 API 後重新載入 | 顯示載入錯誤及可重試入口 |
| 儲存失敗 | 先讀編輯頁，再停止 API，最後儲存 | 保留欄位內容，顯示失敗 |
| 刪除 | 取消一次，再確認一次 | 取消不刪除，確認後移除並刷新 |
| 路由重新整理 | 在編輯頁重新整理 | 開發伺服器仍能載入；正式環境第 18 章驗證 |

Windows PowerShell 可直接驗證後端拒絕非法資料：

```powershell
$body = @{ name = ' '; priceInCents = -1; stock = 2; isActive = $true } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri 'http://localhost:5000/api/products' -ContentType 'application/json' -Body $body
```

這筆請求預期回傳 400，因此 PowerShell 顯示 HTTP 錯誤是驗證結果。若收到 200/201，應檢查後端驗證是否確實接入。

### 13.4 從 Network 反推資料流

新增操作應看到 POST 成功，接著導回清單發出 GET。若清單沒有更新，先確認 POST 回應，再看 GET 是否重新執行、資料是否存在於 API。不要先用重新整理整頁掩蓋狀態失效問題。

**完成條件：**不看教材也能指出一次儲存經過哪些檔案；能從 HTTP 狀態與回應內容判斷問題在畫面、代理、API 契約或後端處理哪一層。
